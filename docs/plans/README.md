# Plans

## Boundary

A plan is a frozen record: research, an audit or a staged proposal, correct as of the date in its header
and never edited afterwards. What it decides goes to an ADR in `docs/adr/`; what gets built and stays
live goes to a mechanism page in `docs/mechanisms/`. A plan that is overtaken gets a successor, not an edit.

## Shape

A dated header with the Linear issue, then the sections the issue asked for. Every claim about the code
names a file and a line at the commit the header gives.

## Filenames

`kebab-case-topic.md`, one file per plan.
